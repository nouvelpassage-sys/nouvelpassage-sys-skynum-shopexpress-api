# Skynum <> Shop-Express API integration

Каркас інтеграції між Skynum та Shop-Express. Основний сценарій тепер такий: Skynum є джерелом товарів, цін і залишків, а Shop-Express є вітриною.

## Що вже закладено

- синхронізація товарів зі Skynum у Shop-Express через `GET /v1/products`;
- оновлення залишків окремим API-запитом;
- передавання фото, якщо в Skynum є URL зображень;
- автозаповнення SEO title/description, якщо вони порожні;
- звіт по товарах, де бракує фото, опису або SEO;
- старий сценарій замовлень залишено як додатковий режим;
- `DRY_RUN`, щоб перевірити payload без запису в Shop-Express;
- конфігуровані API paths, бо точні endpoint-и потрібно підтвердити в кабінетах або офіційній документації.

## Запуск

```bash
copy .env.example .env
node src/index.js --products --once
```

Для постійного запуску:

```bash
node src/index.js --products
```

Замовлення, якщо знадобляться:

```bash
node src/index.js --orders --once
```

Спочатку залиште `DRY_RUN=true`. Після перевірки payload-ів і endpoint-ів можна перемкнути на `DRY_RUN=false`.

## Що потрібно від акаунтів

Shop-Express:

- тариф із доступом до API;
- окремий API-користувач у `Налаштування > API`;
- URL магазину;
- endpoint-и для створення/оновлення товару, залишку і фото.

Skynum:

- API token;
- base URL API: `https://api.skynum.com`;
- products endpoint: `GET /v1/products`;
- залишки: `GET /v1/reports/remains`;
- якщо треба обмежити синхронізацію конкретним складом, заповніть `SKYNUM_STOCK_ID`.

За документацією Skynum API token треба створювати для non-admin користувача з роллю API access. Admin users не можуть робити API-запити.

Важливо: у Skynum зміна залишку не оновлює `updated_at` товару. Тому worker бере товари через `/v1/products`, а актуальні кількості окремо через `/v1/reports/remains`.

## Контент і SEO

Worker може сам згенерувати базові SEO-поля з назви, бренду, SKU і наявності. Для відсутніх фото або слабких описів він створює файл:

```text
reports/product-content-tasks.json
```

Цей файл показує, які картки треба допрацювати вручну або агентом через адмінку Shop-Express.

## Важлива межа по фото

Для реальних товарів найкраще брати справжні фото: зі Skynum, від постачальника або з вашої фотобази. Генерувати AI-зображення можна для заглушок, категорій, банерів або стилізованих сцен, але для товарної картки це ризик: покупець має бачити саме той товар, який отримає.

## Наступні кроки перед production

- підтвердити реальні JSON-схеми Shop-Express і Skynum;
- визначити ключ звʼязки товарів: `sku`, `barcode` або внутрішній `id`;
- перевірити, чи Shop-Express приймає URL фото напряму, чи треба завантажувати файли;
- додати зберігання sync state, якщо API не підтримує reliable `updatedFrom`;
- за потреби підключити browser/Chrome-агента для масового заповнення карток через адмінку.
## Product Assistant Dashboard

Локальна панель для швидкого тестування карток товарів:

```bash
npm run dashboard
```

Після запуску відкрийте:

```text
http://localhost:4177
```

Панель приймає текст у форматі "ціна + коротка підказка + пряме посилання на фото", генерує картку українською та англійською, показує SEO-поля й SalesBox payload. Якщо `SALESBOX_WRITE_ENABLED=false`, кнопка публікації працює як dry-run і не створює товар у SalesBox.
